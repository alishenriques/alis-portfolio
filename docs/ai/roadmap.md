## Fixed along the way
- **Automated npm publish (resolved 2026-09-27, for real this time).** Three distinct bugs, fixed in sequence, each unblocking the next:
  1. `actions/setup-node`'s `registry-url` writes an empty `NODE_AUTH_TOKEN` into `.npmrc`, breaking OIDC auto-detection → 404. Fixed by dropping `registry-url` from the workflow.
  2. No Trusted Publisher was registered for `@alishenriques/design-system` on npmjs.com → `ENEEDAUTH`, then (once a temporary `workflow_dispatch` diagnostic proved the OIDC token exchange itself worked once a Trusted Publisher existed) a `403 OIDC permission denied for this action` on the actual publish. Root cause, found by reading [npm's Trusted Publishers docs](https://docs.npmjs.com/trusted-publishers/) and [GitHub's changelog](https://github.blog/changelog/2026-09-03-multiple-trusted-publishing-configurations-for-npm/): **Trusted Publisher connections created after 2026-09-03 default to "stage publish" only** — direct `npm publish` is a separate, unticked "Allow npm publish" checkbox under "Allowed actions", and an existing connection can't be edited (must delete and recreate). Ours was created on 2026-09-24, squarely inside the new-default window. Fixed on npmjs.com's package settings, not in code.
  3. Even after that, `v0.3.0` and `v0.4.0`/`v0.4.1` published from a **stale local `dist/`** on the user's machine (manual `npm publish` packages whatever's already on disk; it doesn't rebuild). Fixed with a `prepack: yarn build` script in the DS's `package.json`, so both `npm pack` and `npm publish` always rebuild from current source first.
  - `v0.4.3` published via CI with no manual step at all, verified by downloading the real published tarball and grepping its `dist/index.js` for every expected export — first fully automated release.
